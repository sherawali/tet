0 · सबसे पहले — CSV या JSON ?

जवाब : दोनों। पर अलग-अलग जगह, अलग-अलग काम के लिए।
फाइलफॉर्मेटकौन लिखता हैgit पर ?
content/*.csvCSVतू — Excel/Sheets में✅ हाँ, यही तेरा असली डेटा है
dist/*.jsonJSONरोबोट — अपने-आप बनता है✅ हाँ, पर कभी हाथ मत लगाना

एक लाइन में : CSV = तू जो लिखता है · JSON = ऐप जो पढ़ता है। दोनों git पर रहेंगे, पर तू सिर्फ़ CSV छूएगा।

CSV ही क्यों (authoring के लिए)

वजहCSVJSON
Excel / Google Sheets में खुलता है✅ हाँ❌ नहीं
एक typo से पूरी फाइल टूटती है ?✅ नहीं टूटती❌ एक comma गायब = सब बर्बाद
git diff पढ़ने लायक✅ 1 प्रश्न = 1 लाइन❌ पूरी फाइल बदली दिखती है
हिन्दी में quotes/escape का झंझट✅ नहीं❌ \" \\n की किचकिच
किसी और से भरवा सकते हो✅ कोई भी भर देगा❌ coder चाहिए

JSON ही क्यों (ऐप के लिए)

  • Android/Kotlin इसे सीधे पढ़ लेता है, CSV के लिए अलग parser लिखना पड़ता
  • विकल्पों की list, passage का जुड़ाव — ये nested चीज़ें CSV में बेढंगी लगती हैं
  • gzip के बाद बहुत छोटा : 150 प्रश्न = 20 KB
विकल्प B (अगर git भी झंझट लगे) : authoring Google Sheet में कर, और GitHub Action उसे रोज़ अपने-आप खींच ले। तब तुझे git छूना ही नहीं पड़ेगा — बस Sheet में पंक्ति जोड़नी है। चाहो तो ये बाद में जोड़ दूँगा।

दो डिज़ाइन फ़ैसले :

2. topic के नाम manifest में एक बार → हर प्रश्न में «समावेशी शिक्षा» दोहराने के बजाय सिर्फ़ t: 4। 10,000 प्रश्नों पर ये ~400 KB बचाता है

4 · डिलीवरी — और यहाँ एक बड़ा खतरा था

🚨 raw.githubusercontent.com इस्तेमाल किया तो ऐप टूट जाएगा

GitHub के raw endpoint पर rate limit प्रति IP पते लगती है — बिना auth के बहुत कम। और limit पार होते ही वो IP 30 मिनट के लिए पूरी तरह ब्लॉक हो जाता है।

असली दिक्कत ये है :

भारत में Jio/Airtel के मोबाइल यूज़र CGNAT के पीछे होते हैं — यानी हज़ारों यूज़र एक ही public IP साझा करते हैं। तेरे 500 छात्र एक ही टावर से sync करें, तो GitHub को लगेगा एक ही बंदा हमला कर रहा है और सबको ब्लॉक कर देगा।

ऊपर से raw endpoint token भी नहीं मानता, तो limit बढ़ाने का रास्ता भी नहीं।

✅ सही रास्ता — jsDelivr (प्राथमिक) + GitHub Release (बैकअप)

हमारा आकार कितना है : 10,000 प्रश्न ≈ 50 pack × 100 KB ≈ 5 MB। jsDelivr की 50 MB सीमा से बहुत नीचे। फाइलें ~50, उनकी 10,000 वाली सलाह से बहुत नीचे। पूरी तरह सुरक्षित।

jsDelivr की शर्तें पूरी करने के लिए 3 चीज़ें ज़रूरी :
  1. repo public हो
  2. LICENSE फाइल हो (CC-BY-4.0 या MIT चलेगा)
  3. README हो जो बताए ये डेटा क्या है
वरना «general-purpose file hosting» माना जा सकता है, जो उनकी शर्तों में मना है। ये तीनों 5 मिनट का काम हैं और जोखिम शून्य कर देते हैं।
